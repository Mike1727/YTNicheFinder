# Задача для opencode: развернуть проект на этом Windows-сервере

## Что за проект
Воркер `worker/worker.py` ищет через YouTube Data API молодые каналы (до 60 дней, до 10 000 подписчиков)
с аномально успешными видео, определяет их нишу, считает конкурентов и пишет итог в `public/results.json`.
Сайт `public/index.html` (статика) показывает этот файл. Деплой на Vercel идёт из GitHub: каждый push
в `public/results.json` обновляет сайт. Запуск: `run.bat` (создаёт venv, запускает воркер, коммитит и пушит результат).

Логику `worker/worker.py` без необходимости не меняй. Если что-то падает, покажи ошибку целиком,
исправь минимально и объясни, что поправил. Не коммить `worker/.env` и `worker/data.db` (они в .gitignore).

## Шаги (после каждого проверяй результат)

1. **Окружение.** Проверь `python --version` (нужен 3.10+) и `git --version`. Чего нет, установи через `winget`.
2. **Папка.** Распакуй архив `yt-niche-finder.zip` в `C:\yt-niche-finder` так, чтобы `run.bat` лежал прямо в ней.
3. **Ключ.** Скопируй `worker\.env.example` в `worker\.env`. Спроси у меня YouTube API key и впиши в `YT_API_KEY`.
   Если ключа нет, объясни, как получить: console.cloud.google.com, новый проект, Library, YouTube Data API v3, Enable,
   Credentials, Create credentials, API key. Остальные строки не меняй. `LLM_API_KEY` оставь пустым,
   если я не дам ключ (без него работает эвристика). Если дам ключ от Google AI Studio, впиши его и проверь,
   что название модели в `LLM_MODEL` ещё существует.
4. **Тестовый прогон без публикации.** В cmd: `set NO_PUSH=1` и затем `run.bat --searches 2 --validate 1`.
   Должен создаться `public\results.json`. Если есть ошибки API (403, ключ не принят и т.п.), разберись и объясни мне.
   Один такой прогон тратит около 400-500 units квоты из 10 000 в сутки.
5. **GitHub.** `git init`, ветка `main`, первый коммит. Создай приватный репозиторий `yt-niche-finder`
   (через `gh repo create --private --source . --push`, если `gh` есть и авторизован; иначе попроси меня создать
   пустой репозиторий и дать URL). Убедись, что `git push` проходит без интерактивных запросов пароля:
   запуск по расписанию будет без меня.
6. **Vercel.** Подключи репозиторий к Vercel (через Vercel CLI, если он авторизован: `vercel link`, затем `vercel --prod`,
   и `vercel git connect`, чтобы каждый push деплоился сам). Настройки уже лежат в `vercel.json`
   (статика из папки `public`, без сборки). Открой полученный URL: должна быть страница «Свободные ниши YouTube»
   с сообщением, что данных пока нет (или с результатами тестового прогона).
7. **Расписание.** Создай задачу Планировщика Windows «YT Niche Finder»: раз в сутки (например, в 04:00)
   запускать `C:\yt-niche-finder\run.bat` без аргументов. Задача должна выполняться, даже если я не подключён по RDP.
   Если используешь учётную запись SYSTEM, проверь, что у неё работают git-учётные данные для push
   (например, токен в URL remote). Проверь, запустив задачу вручную (`schtasks /Run`) и посмотрев `worker\run.log`.
8. **Отчёт.** Напиши мне: URL сайта, время запуска по расписанию, сколько units квоты потрачено, и что осталось
   нерешённым.

## Полезно знать
- Пороги и бюджет квоты меняются в `worker\.env` (см. комментарии в `.env.example`), стартовые запросы для поиска в `worker\seeds.txt`.
- Один запуск по умолчанию: 20 поисков (около 2 000 units) плюс проверка до 15 кандидатов (около 300 units каждый),
  итого не больше 9 000 units в сутки.
- Лог работы: `worker\run.log`. База с кэшем и счётчиком квоты: `worker\data.db` (удалять не нужно).
- Флаги воркера: `--searches N`, `--validate N`, `--no-discovery`, `--export-only`, `--budget N`.
